第七章 设备管理



7.1 设备管理的基本概念



设备管理是操作系统中负责管理各种输入 / 输出设备的组成部分。



从用户角度看，设备管理的目标很简单：



让用户和程序能够方便、统一地使用各种硬件设备，

而不需要关心设备的具体工作细节。



但从操作系统角度看，设备管理需要解决的问题要复杂得多，包括：

不同类型设备的统一管理

多个进程对设备的共享与竞争

提高 I/O 效率，减少 CPU 等待

保证设备使用的安全性和可靠性





7.2 I/O 设备的分类



按设备功能分类



从功能角度看，I/O 设备通常可以分为：

输入设备（如键盘、鼠标）

输出设备（如显示器、打印机）

输入 / 输出设备（如磁盘、网卡）





按数据传输方式分类



按数据传输方式，设备可分为：

字符设备:

以字符为单位传输数据，例如键盘、串口设备。

块设备:

以数据块为单位传输数据，例如磁盘设备。



这种分类方式对设备驱动和文件系统设计非常重要。





7.3 I/O设备的控制方式



设备管理的核心问题之一是：



CPU 如何与外部设备进行协作。





程序直接控制方式



在这种方式下：

CPU 主动轮询设备状态

等待设备完成操作



这种方式实现简单，但存在明显缺点：

CPU 利用率低

不适合复杂系统



因此，在现代操作系统中几乎不使用。





中断驱动方式



中断驱动方式的基本思想是：

CPU 启动 I/O 操作后继续执行其他任务

设备完成操作后，通过中断通知 CPU



这种方式显著提高了：

CPU 利用率

系统并发能力



现代操作系统普遍采用中断驱动方式。





DMA 方式（直接内存访问）



DMA 的基本思想是：



由 DMA 控制器直接完成设备与内存之间的数据传输，

减少 CPU 的参与。



DMA 方式的优点包括：

减轻 CPU 负担

提高数据传输效率



DMA 常用于：

磁盘 I/O

网络数据传输





I/O 软件的层次结构：



为了提高系统的可维护性和可扩展性，

操作系统通常将 I/O 软件划分为多个层次。



一般包括：

用户层 I/O 软件

与设备无关的 I/O 软件

设备驱动程序

中断处理程序



这种分层结构的好处在于：



上层不需要关心具体设备细节，

下层专注于硬件相关操作。



7.4 设备分配与回收



设备分配



当进程请求使用某个设备时，操作系统需要：

判断设备是否空闲

分配设备给请求进程

建立相关的数据结构





设备回收



当进程使用完设备后，操作系统将：

回收设备

更新设备状态

唤醒等待该设备的其他进程



设备分配与回收需要防止：

设备长期占用

进程饥饿







7.5 设备驱动程序



设备驱动的作用



设备驱动程序是操作系统中：



直接与硬件设备打交道的软件模块。



设备驱动的主要作用包括：

控制设备工作

屏蔽设备差异

向操作系统提供统一接口



从系统角度看，驱动是“最接近硬件的软件”。





设备独立性



设备独立性是指：



操作系统通过统一接口，使上层软件不依赖具体设备型号。



例如：

程序只关心“读文件”，而不关心数据来自硬盘还是 SSD



设备独立性提高了系统的：

可移植性

可维护性





7.6 缓冲技术



7.6.1 缓冲的作用



由于 CPU 与 I/O 设备之间速度差异较大，

操作系统通常引入缓冲机制。



缓冲的主要作用包括：

缓解速度不匹配问题

减少 I/O 次数

提高系统吞吐量





7.6.2 缓冲方式



常见的缓冲方式包括：

单缓冲

双缓冲

多缓冲



缓冲机制在磁盘 I/O 和网络通信中非常常见。
