第三章 进程/线程模型



3.1 进程的基本概念



3.1.1 程序与进程的区别



程序（Program） 是一组静态的指令集合，存放在磁盘等存储介质中。

进程（Process） 是程序的一次执行过程，是一个动态概念。



两者的核心区别在于：

程序是**静态**的

进程是**动态的、正在运行的**

一个程序可以对应多个进程

进程是操作系统进行资源分配和调度的基本单位



3.1.2 进程的定义



进程通常被定义为：

程序的一次执行过程，以及执行过程中所需的系统资源的集合。



从操作系统角度看，进程至少包含：

**程序代码**

**数据段**

**运行时状态信息**

**系统资源（如打开的文件、占用的内存等）**



3.2 进程的特征

进程具有以下基本特征：



（1）动态性



进程是程序的执行过程，具有创建、执行和撤销的生命周期。



（2）并发性



多个进程可以在同一时间段内并发执行。



（3）独立性



进程是系统进行资源分配和调度的独立单位。



（4）异步性



进程的执行速度和顺序不可预测。



3.3 进程的组成

一个进程通常由以下几部分组成：

程序段：要执行的代码

数据段：全局变量、静态数据

进程控制块（PCB）



其中，进程控制块（PCB） 是进程存在的唯一标志。



3.3.1 进程控制块（PCB）



PCB 中通常包含以下信息：

进程标识符（PID）

进程状态

程序计数器

CPU 寄存器状态

内存管理信息

I/O 状态信息



操作系统通过 PCB 来：

管理进程、实现进程切换、保存和恢复进程运行状态



3.4 进程的状态与转换



3.4.1 进程的基本状态



常见的进程状态包括：

就绪状态（Ready）

进程已具备运行条件，等待 CPU 分配。

运行状态（Running）

进程正在 CPU 上执行。

阻塞状态（Blocked）

进程因等待某事件而暂停执行。





3.4.2 进程状态转换

进程在执行过程中，会在不同状态之间转换：

就绪 → 运行：获得 CPU

运行 → 就绪：时间片用完或被抢占

运行 → 阻塞：等待 I/O 或事件

阻塞 → 就绪：等待事件完成



进程状态转换由操作系统内核控制。



3.5 进程的创建与终止



3.5.1 进程的创建



进程可以通过以下方式创建：

系统初始化

用户请求（如启动应用程序）

一个进程创建子进程



创建进程时，操作系统需要：

分配 PID

建立 PCB

分配必要资源





3.5.2 进程的终止



进程终止的常见原因包括：

正常执行完毕

程序错误

外部请求终止



终止进程时，操作系统将：

回收资源

删除 PCB





3.6 线程的基本概念



3.6.1 线程的定义



线程（Thread） 是进程内的一个执行单元，



**是 CPU 调度的基本单位。！！！**



一个进程可以包含多个线程，这些线程：

共享进程的地址空间

共享进程资源

独立执行



3.6.2 线程引入的原因

引入线程的主要原因包括：

提高并发程度

减少创建和切换开销

提高系统响应速度





3.7 进程与线程的区别与联系



3.7.1 进程与线程的区别

从系统角度看：

进程是资源分配的基本单位

线程是 CPU 调度的基本单位

进程间切换开销较大

线程间切换开销较小





3.7.2 进程与线程的联系

一个进程至少包含一个线程

同一进程内的线程共享资源

线程依赖于进程存在





3.8 多线程模型（概述）



常见的多线程实现方式包括：

用户级线程

内核级线程

混合线程模型



不同模型在：

性能

实现复杂度

系统支持

方面存在差异。



3.9 本章小结

本章主要介绍了：

进程与程序的区别

**进程的组成与状态**

进程控制块（PCB）

**线程的基本概念**

进程与线程的关系



进程与线程是操作系统中最核心的概念，也是理解 **调度、同步、并发、死锁** 等内容的基础。！！
